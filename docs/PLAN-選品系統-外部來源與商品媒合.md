## 一頁結論

**題目：外面找回來一堆商品（蝦皮／1688 榜單、中盤商目錄、LINE 社群機器人），
不知道拿哪一項。系統要回答「這一項在我這裡會不會中」，開了團之後把結果記回來，
下一次更準。**

做法是「賭商品、不賭人」：每開一團是一次下注，結果回寫到該類別、該屬性的勝率，
下次選品用更新過的勝率排序。不做個人化、不做社群分眾、不做商城推薦排序。

三個前提：

1. **訂單 46% 來自 LINE +1、19% 店員手 key、只有 31% 走商城 app。** 所以「吸引力」
   的訊號是留言＋下單，不是 app 點擊；商城排序影響不到七成生意，不做。
2. **87% 商品只開過一次團。** 統計累積在「類別／屬性」，不在單一商品。
   外部商品要先媒合到「我賣過最像的」和「同類」才有歷史可借（§2.1）。
3. **標籤斷了。** 4,390 個商品只有 39% 有標籤，近 30 天新增 960 個、0 個有標籤
   （規則只在 8/9 跑過一次）。8/9 回測證明標籤是預測主力，不修這個後面全部失效。

## 二、流程

```
外部來源                    媒合（Claude+SQL）        選品分數                 開團           回寫
蝦皮助手 / 店雷達 匯出  →  正規化品名 + 標籤 →  類別勝率 × 最像商品歷史  →  老闆挑  →  24h 留言/訂單
中盤商目錄（Excel）          找我賣過最像的 5 個     × 市場熱度 × 價格帶          開團       7 天滲透率
LINE 社群機器人              去重（已賣過？）        × 擁擠度 × 廠商評分                     更新類別勝率
                                                     × 季節 × 毛利；溫層過濾                  每週回測 ρ
```

- **進料**：先用匯出的 Excel 上傳，不寫爬蟲。進 `market_products`
  （來源、外部 id、商品名、類目、售價、近 7/30 日銷量、成長率、抓取日）；
  中盤商目錄進 `supplier_catalog_items`（廠商、品名、規格、進價、溫層、最小訂量）。
  兩者都進既有候選池 `community_product_candidates` 的同一頁給老闆看，`source` 多兩個值。
- **出口**：候選池每一項多幾欄：分數、信心、理由（「同類近 4 週滲透率 2.8%、
  最像的是 X 當時 3.1%、蝦皮同類週成長 40%、廠商中位 7 天到」）、反面清單（你賣過、賣不動）。
- **留 10% 探索槽**給勝率不明的類別，不然永遠只開已經會賣的。

### 2.1 媒合：Claude 正規化 + Supabase 字詞比對（不用向量，2026-11-01 改）

外部商品名跟你的寫法完全不同（「Shine Muscat」對「麝香葡萄」、簡繁體、蝦皮標題關鍵字堆疊），
直接字串比對抓不到。原本規劃用向量，老闆決定**不加其他服務**（向量要另一家的 embedding API），
改成只用既有的 Claude API + Supabase：

1. **Claude 正規化**：每筆外部商品丟給 Claude（`product-tag` 同一套），回「標準繁中品名
   （去掉行銷字、英文翻中、簡轉繁）＋ 標籤」。例：「Shine Muscat 晴王葡萄 2kg」→「麝香葡萄 晴王」＋ fruit。
2. **SQL 二字詞比對**：正規化品名切成二字詞，算在我方商品名裡命中的比例，同標籤優先，取前 20 個候選。
3. **Claude 挑最像的**（選用）：前 20 個候選再丟回 Claude 選出真正同款／同類的 5 個、判斷「是否已賣過」。

2026-11-01 實測（正規化由人工模擬 Claude 的輸出，比對對全部 4,390 商品跑 SQL）：
「Shine Muscat 晴王葡萄」→ 韓國麝香葡萄 ×3；「挪威鲭鱼片 冷冻」→ 挪威嚴選鯖魚片；
「Korean instant coffee mix」→ 韓國咖啡糖、韓國濃縮美式；「黑青稞粑粑粉」→ 沒有命中（＝沒賣過，正確）。

為什麼不用 Supabase 內建的轉向量模型 gte-small：它是英文模型。同一批 600 個已標商品測
「最近 5 個鄰居投票猜類別」只對 31.5%（多語言模型 51.2%），「晴王葡萄」對到雞米花、
「鯖魚片」對到牙套收納盒，不能用。

**分數本體仍是類別層級統計**——8/9 回測「找相似品借歷史」ρ=0.322 沒有比類別平均 0.32～0.36 準，
媒合只是用來找參考商品和去重。以後商品量大到幾十萬、或要做圖片相似，再考慮向量。

### 2.2 外部榜單的限制

蝦皮、1688 榜單對**非食品**（居家、清潔、收納）有覆蓋，對你營收主力的**生鮮食品**
（葡萄、雞蛋、鯖魚）幾乎沒有。非食品佔訂單約 14%，但是平日補量的類別。
食品那塊的外部來源還是 LINE 社群機器人和廠商。蝦皮爆款是單件低價衝量，
團購是整箱吃的，市場熱度權重要低於「我的客人偏好」。

## 三、選品分數的維度（本次實查）

| 維度 | 證據（近 150 天） | 用法 |
|---|---|---|
| **類別勝率** | 8/9 回測單獨 ρ=0.32，主力 | 該類近 4 週滲透率，貝式平滑、半衰期 5 天 |
| **最像商品歷史** | 媒合 5 個（§2.1） | 顯示當時滲透率，當參考與信心來源 |
| **價格帶**（最強的單一特徵） | 單價 <200 平均 32～37 位買家、200～300 剩 21、300 以上 ≤6 | 售價 >300 大幅扣分 |
| **同類擁擠度** | 同類一週開 16 團以上，每團買家 27 vs 34（−20%） | 看「這類本週已開幾團」 |
| **市場熱度** | 蝦皮／1688 近 7 日成長率 | 對得上同類才加分，權重低 |
| **廠商評分**（見 §四） | 到總倉 29 天以上的單取消率 6.2%，7 天內 2～2.5% | 慢＋常斷貨的扣分 |
| **季節／節慶** | 歷史只有 5 個月，學不到 | 先用月曆規則（鍋物 11～2 月、冰品 6～9 月、禮盒節前 3 週） |
| **毛利** | 中盤商目錄有進價 | 配習慣售價算 |
| **星期規律** | 只有穩定的那幾類：清潔／日用／居家平日高週日掉、麵包週日高 | 當提示，不當分數 |
| 溫層／可行性 | 冷凍品看店家冰箱、到貨天數 | **過濾條件**，不打分 |

之後再加：類別取消／未取率、品牌（`brand_id` 累積夠再用）。
天氣、發薪日先不要，沒資料驗證就是猜。

星期規律要小心：150 天與 9/8 之後兩段對比，零食餅乾、名產伴手禮、海鮮的規律**相反**，
那是當週開什麼團造成的，不是客人習慣。只有兩段都成立的才能用。

## 四、廠商評分（新頁面）

採購送出 → 總倉首次收貨，近 150 天 1,590 張已收採購單：中位 7.3 天，
四分之一 1 天內到，**三分之一超過 14 天**，最慢一成 27 天以上。
差異主要在廠商，不在類別：同一類換廠商可差三週。

到總倉越慢，客人取消越多：

| 採購到總倉 | 採購單 | 連動訂單取消率 |
|---|---|---|
| 0～3 天 | 497 | 2.5% |
| 4～7 天 | 263 | 1.9% |
| 8～14 天 | 301 | 2.9% |
| 15～28 天 | 380 | 3.6% |
| 29 天以上 | 149 | **6.2%** |

最慢的幾家（中位天數 / >14 天比例 / 斷貨率 / 連動訂單取消率）：
米嵐 28.5 天 / 95% / 22% / 13.0%；金鑽 26 / 79% / 35% / 11.4%；
陸貨（山瀾商行）17 / 67% / 21% / 8.8%（牽到 14,011 張單，影響最大）；
實宸 14 / 50% / 17% / 16.4%。對照：晨一 11.5 天 1.2%、兆洋 15 天 1.0%。
**慢又常斷貨**的才是客訴來源。沅裕 8 天就到、取消率 19.8%，是別的問題（品質／規格），另查。
整體在變好：6 月中位 15 天、53% 超過 14 天 → 10 月中位 6 天、17%。

頁面欄位：每家廠商的採購單數、中位天數、>14 天比例、斷貨率、連動訂單取消率、逐月趨勢；
點進去看該廠商每張單。選品分數直接帶這個分數；中盤商目錄進來先看廠商是誰。

算法：`COALESCE(po.sent_at, po.created_at)` → `min(goods_receipts.confirmed_at / receive_date)`
（排除 cancelled）；連動訂單走 `purchase_request_items.source_campaign_id`
→ `purchase_order_items` → `customer_orders`。

後段「總倉到分店」（結單到 `ready_at`：生鮮中位 11.5 天、食品 13.5、非食品 20）是自己的
撿貨速度，跟選品無關，另外看。準時率要等「預計到貨日」有人填才算得出來。

## 五、分階段

### Phase A — 資料接上（1 週）

| 要做 | 為什麼 |
|---|---|
| 新品上架自動貼標：Claude 看商品名回標籤，寫 `product_tag_map`（`source` 加 `'llm'`）；先補掉 960 個 ✅ #1101 | 標籤是一切的基礎 |
| `campaign_daily_stats(date, campaign_id, orders, buyers, comments, cancelled, viewers)`，pg_cron 每晚聚合 ✅ #1101 | 看得到「第一天賣多少」，回寫與回測都要它 |
| 選品機器人補記「來自哪個社群」（`source_channel`）✅ #1101（Apps Script 端要送 groupId / groupName） | 現在 4,217 則不知道從哪來 |
| 採購單開始填「預計到貨日」（UI 預設帶廠商歷史中位天數） | 之後才有準時率 |

**不做**：曝光紀錄、貼文連結帶來源、個人推播、商城排序。前面決定不走人與社群。

### Phase B — 進料與媒合（2 週）

- `market_products`、`supplier_catalog_items` 兩張表 + Excel 上傳頁（欄位照實際匯出檔定）。
- 上傳後由 Edge Function 批次送 Claude 正規化（標準品名＋標籤），寫回 `norm_name`、`tags`。
- `rpc_match_external_product(id)`：§2.1 的二字詞比對取前 20 候選（同標籤優先），
  回最像的 5 個已賣商品（含當時滲透率）與「是否已賣過」；需要時再請 Claude 從 20 個裡挑。
- 驗收：拿最近 3 個月的候選池，人工抽 50 筆看「最像商品」對不對，命中 ≥ 80% 才上線。

### Phase C — 分數、回寫、廠商評分（2 週）

- `rpc_supplier_scorecard(p_days)` + 後台「廠商評分」頁（§四）。✅ 提前在 #1101 做掉
- `rpc_candidate_score(candidate_id)`：§三的維度 → 分數、信心、理由文字；候選池頁面加欄、可依分數排序、反面清單。
- 回寫：開團 24 小時 / 7 天的結果寫回類別勝率（Beta 後驗：成功＝滲透率達該類中位以上）；
  排序時 Thompson Sampling 抽樣，10% 探索槽。
- 每週自動回測（沿用 `scripts/analysis-campaign-demand-backtest.py` 架構），ρ 寫進一張表。
- 看板一頁：類別近 14 天勝率、推了沒人理的團（貼了 ≥3 個社群、24 小時 0 留言）、穩定的星期規律。

### Phase D — 之後

品牌特徵、類別取消／未取率、季節改成學的（滿一年）；量大到字詞比對不夠用時再上向量。

## 六、驗收

| 指標 | 現在 | 目標 |
|---|---|---|
| 標籤覆蓋率 | 39% | ≥ 95% |
| 自動貼標 precision | — | ≥ 0.85 才自動寫入 |
| 候選分數 vs 實際滲透率 Spearman ρ（每週） | 8/9 回測 0.36 | ≥ 0.40；掉到 0.30 以下要重訓 |
| 0 買家團比率 | 8.4%（8/9） | < 5% |
| 分數前 20% vs 後 20% 實際滲透率 | 2.4 倍 | 維持 ≥ 2 倍 |
| 慢廠商（中位 >14 天）承接的訂單占比 | 待算 | 逐月下降 |

## 七、坑

1. 不要拿 app 瀏覽當全部的點擊，七成訂單不經 app。
2. 分母一定是觸及（社群數／店數），不是全站。
3. 長得像 ≠ 會賣，媒合只用來找參考商品與去重。
4. 正規化提示詞改了，外部商品要整批重跑正規化，舊的 `norm_name` 不能跟新的混著比。
5. 自動貼標要有人工覆寫且重跑不覆蓋，沿用 `product_tag_map.source` 語意。
6. 樣本不足顯示「資料不足」，不硬給分數。
7. 熱度高 → 多開 → 更熱的迴圈，從第一天就留探索槽。
8. 星期規律只用兩段資料都成立的；單一期間的規律多半是開團時機造成。
