# 測試項目 — 取貨頁「已取貨」模式（篩選已取訂單 → 合併補印收據）

**範圍:** 純前端 UI。取貨頁（`/pickup`）原本只查未取訂單（`ACTIVE_STATUSES`），新增「未取貨 ↔ 已取貨」切換：同一個搜尋框查出該會員**已取走**的訂單，勾選後**合併成一張**收據補印 —— 等同未取貨那邊「一次全取 → 列印小白單」的合併體驗。無 schema / RPC 變更，列印頁不動。

**對應變更（`apps/admin/src/app/(protected)/pickup/page.tsx`）:**
- `mode: "open" | "picked"` 切換鈕（標題文案跟著換）；切換即用同一個關鍵字重查、清掉勾選。
- `search()` 依 mode 換條件：
  - `open`（原行為）：`ACTIVE_STATUSES`，`ready_at ASC NULLS LAST`
  - `picked`：`PICKED_STATUSES = [completed, partially_completed]`，`completed_at DESC NULLS LAST`，上限 `PICKED_LIMIT = 50`
  - `picked` 模式不查到貨狀態 / 未取退貨（與補印無關），改查 `fetchReprintableEvents()` 拿每張單可補印的取貨事件。
- 已取貨清單：每列顯示已取品項、金額、最後一次取貨時間（多次取貨標「共 N 次」、hover 看每次時間），一顆單張「🖨️ 補印」。
- 會員卡右上「🖨️ 合併列印（N 張）」→ **先跳確認視窗**（版型對齊「一次全取」：張數 / 項數 / 小計−折扣 / 每張的品項與取貨時間）→ 按「🖨️ 合併列印」才送印，把該會員**所有可補印的**（有勾選時只算勾選的）訂單事件 id 合成**一個** `/pickup/print?event_ids=…` → 印出一張。
- 取貨已被撤銷（`pickup_undone`）的單：標「⚠️ 無取貨紀錄可補印」、勾選框 disabled、不列入合併。

**順手修掉的既有 bug:** `search()` 原本只認 `query` state，而「常用顧客快選」與 `/members` 帶 `?q=` 進來時**刻意不寫進搜尋框**。因此那兩條路進來後的任何重查（取貨完 `reloadTick`、本次的模式切換）都會誤判成沒有關鍵字，跳「請至少輸入 2 字」並停在舊資料上。改法：`lastSearchRef` 記住最後一次查成功的字串當 fallback，自動搜尋也改成明確傳 `?q=` 值。

**驗證方式:** `tsc --noEmit` + eslint（該檔問題數 2 → 1，未新增）+ Playwright fixture（`apps/admin/.claude/skills/verify`，攔 `rest/v1` 回假資料，不碰線上 DB）。
