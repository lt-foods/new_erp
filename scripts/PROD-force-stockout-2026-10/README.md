## 這次改了什麼

- 採購單編輯頁，**已經收過貨**的那一項，多一顆「已到貨也能斷貨」。只有名單上的人看得到、按得了（老闆 10/22 定案：只開給老闆與 Alex）。
- 按下去先跳確認視窗：會取消幾位客人、幾件、哪幾家店、哪幾團；哪些單會整張取消、哪些收尾完成、哪些單子留著；不動的（已取貨、店家已經取消的、付過錢的）；擋下的原因；貨派到哪幾家店、收了沒。
- 要**手打商品代碼**、**填原因**才按得下去；「同時發斷貨通知」預設不勾。
- 確定之後：這一項對應那張請購單的團裡、這個商品、還沒取貨的客人品項一次取消（跟契爾氏那次 #1087 同一套規則），每一筆留編輯歷史（誰、什麼時間、原因）。
- **不動**：採購單那一項（不標斷貨）、開團商品、派車單、庫存、月結、退回單。實體貨照現在的流程退回（畫面會列待辦）。

## 怎麼用（給老闆與 Alex）

1. 採購單編輯頁，已經收過貨的那一列，右邊「斷貨」欄會多一顆「已到貨也能斷貨」。
   - 那一列如果還在等貨（部分到貨），只會看到原本的「⛔ 斷貨」；兩顆不會同時出現在同一列。
   - **部分到貨（還沒收滿）的品項這次不支援**（CEO 10/22 裁定）。
2. 按下去先看確認視窗：人數、件數、店家、團號都對了，再打商品代碼、填原因，按「確定取消」。
3. 按完畫面會列「回收貨的待辦」，照著做：
   - **店家已收貨**：店家到「退貨」頁開退回單退回總倉 → 總倉到「總倉收件匣 → 🚚 轉貨單 → ↩ 退貨回總倉」按「同意收回」。
   - **店家還沒收**：店家收貨時這一項實收改 0 → 總倉到「總倉收件匣 → ⚠️ 異常 → 店家少收」按「同意退」→「不補貨」。
   - **上面兩種按完之後，那批貨會凍結、派不出去**（#924 10/22 已上線）：要到左選單「倉儲 (WMS) → 退回貨處理」處理才解凍。
     那一頁填「完好數量」（要勾「實物已到總倉」）＝恢復成可再派出的庫存；填「破損數量」或「遺失數量」（要填原因）＝記入總倉損失；填完按「送出處理」。
   - **錯貨要退廠商**：退回貨處理頁沒有「退廠商」選項，先在那一頁處理完，再走採購單退貨；選「完好」的話那批貨會回到可派出的庫存，小心不要又派出去。
   - **撿貨單還沒派車**：這一項先不要派出去，請總倉在撿貨單上處理。

## 出問題時

- **只想先關掉**：貼 `kill_switch_20261022100000.sql`（清空名單）。要再開：重貼開權限。
- **整個還原**：貼 `rollback_20261022100000.sql`。前端已經上線的話，按鈕自動不出現，其他功能照常。
- **按錯了想救回**：這次沒有復原鈕（老闆 10/22 定案）。後台訂單頁的「復原取消」對斷貨取消的單不會出現、採購單的「回復斷貨」也認不得這種取消 ⇒ 要救只能另外寫 SQL（每一筆的編輯歷史原因都寫著「已到貨斷貨（採購單品項 #N）：…」，認得出是哪一次）。

## 危險（兩邊都講）

- **貼了會怎樣**：名單上的人按一下，就會把那張請購單涵蓋的**所有團**裡、這個商品、還沒取貨的客人一次取消，而且沒有復原鈕。
  - 降低方法：只開給兩個人；要打商品代碼；確認視窗列出每一團、每一家店的件數；同一團同一商品還有別張採購單就擋下。
  - 付過錢或用過儲值金的單：品項照樣取消，**錢不會動**，畫面會列出單號，要人工確認退款。
  - 單上還有別的商品、單子留著的客人：店家之後收這批貨時，系統可能照舊發一則「您的商品到貨」（這是現在就有的行為，斷貨、刪除品項也一樣）。
- **不貼會怎樣**：每次遇到這種事都要像契爾氏那次寫 SQL、審查、再貼，花一整天；那段時間客人的訂單一直掛著等貨。
- **還原會怎樣**：只拿掉程式和名單；已經取消的客人品項不會被改回來。

## 已知做不到（這次不處理）

- **部分好貨、部分壞貨**：按下去會取消全部還沒取貨的客人 ⇒ 這種情況不要用這顆鈕。
- **補貨申請（店家叫的 RR- 內部單）**：不處理；確認視窗會寫這一項有幾筆補貨申請。
- **回收實體貨**：照現在的流程（店家收貨改 0／開退回單 → 總倉「同意收回」或「店家少收」的「同意退」→「不補貨」 → 「退回貨處理」頁處理才解凍 → 要退廠商再走採購單退貨），系統不會代替。
- **部分到貨（還沒收滿）的品項**：這次不支援，那一列只會看到原本的「⛔ 斷貨」。
- **會被整張取消的單，以前取消過又被救回**（取消時間不是空的）：會擋下，請找工程師人工處理。
