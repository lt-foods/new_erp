## 這次改了什麼

- **手機團控可以重開**：已關團或已鎖定的團，只要它連到的請購單**全部還是草稿**、而且沒有任何品項轉成採購單，就可以重開。請購單已經送出，就擋下，並用中文告訴你是哪一張。
- **關團只補差額**：重開後再關團，併進當天的請購草稿時，只加「新增的那些」，不會再整團重加一次。
- 只換了兩支資料庫函式，**沒有改任何資料表，也沒有改任何一筆舊資料**。

## 三步驟

### ① 挑沒人在關團的時段，貼 migration

- 貼 `supabase/migrations/20261001020000_reopen_draft_pr_and_delta_append.sql`。
- 時段要選沒有人在後台關團、建請購單的時候，例如早上開工前。
- 檔案最前面有前置檢查，缺東西會直接停下，一行都不會改。整份貼兩次也沒關係。
- ⭐ 建議**貼之前**先跑一次 `postcheck_readonly.sql` 並截圖。這時「新版」那幾列會是 ❌，那是正常的；截圖是為了跟貼完之後比對「相關函式」那幾列的 md5 有沒有變。

### ② 貼 `postcheck_readonly.sql`，要全部 ✅

- 最後一列「總結」要是 ✅。
- 「相關函式沒被改到」那幾列的 md5，應該跟貼之前的截圖一模一樣。
- ℹ️ 開頭的列只是紀錄，不用判斷對錯。

### ③ 實際試一次

1. 找一個團，在手機團控按「關團」。關完到那天的請購草稿，按「同步最新開團數量」預覽，**應該是 0 差異**。
2. 重開各試一次：
   - 請購單還是草稿的團 → **可以重開**。
   - 請購單已經送出的團 → 會看到中文的「請購單 ○○○ 已送出，不能重開；要加量請到請購單頁」。

### 任何一步有 ❌、或預覽有差異 → 貼 `rollback_20261001020000.sql`

- 它會把兩支函式**逐字換回** 10/1 以前的版本，最前面會先確認「這是正式庫」以及「目前確實是新版」。
- 換回之後就回到舊行為：已鎖定的團不能重開；重開後再關團**會整團重加**。所以還原之後，已經重開過的團先不要再關，先找工程師。
- 已經記下的「來源團明細」不會被刪，那些數字本來就是對的，其他補單、同步功能會繼續用。

## 危險（兩邊都講）

- **貼了會怎樣**：包子媽在請購還是草稿時可以重開團，再關團時只補差額。這兩支函式碰到叫貨數量，寫錯會多叫或少叫，所以第 ③ 步一定要做。
  - ⚠️ 請購單上如果有「沒有來源團明細、又不是這個團的舊資料」，關團時會**併不進去**（團停在已關團，沒有進請購單）。畫面會提示，看到就到請購單頁用「結單日補請購」補。
- **不貼會怎樣**：已鎖定的團照舊打不開，包子媽只能另開新團。另外畫面 T3 已經讓已鎖定的團可以按「重開」：如果畫面先上線、這份 migration 沒貼，按下去會被資料庫用舊的英文訊息擋掉。
