## 這次改了什麼

- 商品頁「建立開團」選限量，商品有 2 個以上啟用中的規格：每個口味各一格上限。全填＝各口味分開算；全空＝填總量；只填一部分不能送出。
- 「編輯開團」視窗的「量上限」欄：限量團、草稿或開團中、手機團控那組角色可以改，按「存」馬上生效。
- 下單、後台加單、記事本留言本來就照口味上限擋，**沒有改**。
- **貼 SQL 不會改任何舊團、訂單或帳**，只換「從商品建團」那支程式。

## 檔案

| 檔 | 會不會寫入 | 用途 |
|---|---|---|
| `postcheck_readonly.sql` | 只查不改（一句、一個分號） | 貼 migration 前跑一次、貼完再跑一次，看「總結」 |
| `rollback_20261105000000.sql` | **會改** | 換回 12 參數的舊版 |

## 順序（先貼資料庫，再合併前端）

1. **貼之前**：跑 `postcheck_readonly.sql`。「現況」要是「舊版（12 參數）」，「總結」要是「尚未貼」。⚠ 開頭是「不是預期的版本」就先停，截圖給 CEO。
2. **半夜貼 migration**。最前面有前置檢查：線上跟預期的版本不一樣會整份停下、一行都不改。整份貼兩次也沒關係。
3. **再跑 `postcheck_readonly.sql`**：①②③④ 全 ✅、「總結」✅。
4. **全部 ✅ 之後才合併前端。**
   - 反過來先合併前端：其他類別照常，但「限量＋每個口味都填」會建團失敗（顯示找不到函式），不會建出半套的團。
5. 合併後抓線上程式找特徵字確認上線（例：「每個口味各限量多少」），再實際建一個測試限量團，三個口味各填不同上限，到「編輯開團」和「進度」頁看三行上限。

## 還原

1. 前端如果已經合併：先把前端退回（不然還原後「限量＋每個口味都填」會失敗）。
2. 貼 `rollback_20261105000000.sql`。
3. 跑 `postcheck_readonly.sql`：「現況」＝舊版（12 參數），「總結」＝尚未貼。

還原不會動已經建好的團；它們的口味上限留在團裡，照常有效。
