# 金管會（FSC）合規

> **重要界定**：法遵**認證屬銀行（受監理機構）責任**，不在本平台建置範圍。平台的角色是**提供支援銀行履行義務的控制項與證據**。

## 1. 適用法規（銀行端義務，平台支援）

- 金融機構安全維護管理辦法
- 金融機構提供自動櫃員機系統安全作業規範
- 金融業導入零信任架構參考指引（路線參考）
- 委外作業相關規範（MDS 為受委託營運者 → 委外監督）

## 2. 平台提供的合規控制項

| 義務面 | 平台支援 |
|---|---|
| **異常提領監控** | 交易監控 + 規則/（v2）ML 異常偵測 → 告警（見 `42`/`51`）|
| **異常事件通報（銀行局）** | 異常通報工作流：偵測→分類→通報單→時效追蹤→歸檔，及報表模板 |
| **稽核軌跡** | hash chain 防竄改稽核（見 `30` §3），含 EJ 存取 |
| **權限/職能分離** | RBAC + maker-checker + MFA（見 `50`）|
| **資料保留** | 可設定之 EJ/交易/稽核保留期 + 不可變儲存 + legal hold |
| **委外監督** | MDS Operator 操作全稽核、租戶隔離、可供銀行查核之報表 |
| **演練（drill）** | 支援故障/通報流程演練紀錄 |
| **弱掃/滲測證據** | 漏洞掃描/修補追蹤之證據管理 |

## 3. 異常事件通報工作流

```
偵測（規則/ML/人工）→ 判定是否應通報 → 建通報單（分類/影響/時間線）
   → Compliance 覆核 → 於時限內通報銀行局 → 追蹤回覆 → 歸檔（稽核）
```
- 與通知引擎連動（通知 Compliance）；及時率納 KPI（見 `00-overview/01`）。

## 4. 資料落地與保留

- on-prem 部署：資料全留行內（見 `12`）。
- SaaS：依銀行所在地選區。
- 保留期：依金管會/銀行政策設定（常為多年）；到期前不可刪、可 legal hold。

## 5. 零信任路線（Phase 3）

- 對應金管會零信任參考指引：身分為核心、最小權限、持續驗證、微分段、裝置信任（機端憑證/姿態）。
- 逐步強化：mTLS（已具）→ 細粒度授權 → 持續風險評分 → 自適應存取。

## 6. 待客戶確認（影響合規設計）

- 金管會報表確切格式與保留年限（`07-delivery/71` Q6）。
- 各銀行部署模式（on-prem vs SaaS）影響資料落地（Q1）。
- 是否強制特定 DB/加密模組（Q5）。

> 平台設計使銀行「容易通過」金管會檢查，但**不代替**銀行完成認證。
