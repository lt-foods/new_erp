# 願景與業務目標（Vision & Goals）

## 1. 背景

客戶 **MDS 三商電腦**深耕台灣金融自動化 40+ 年，為 Hitachi Channel Solutions ATM 台灣獨家代理，在存提款／循環式 ATM 市場具領導地位。其現有產品 **DMS 自動化設備監控管理系統**為銀行提供 ATM/AVM 機隊集中監控管理，已具備：

- 即時色彩狀態看板（機台狀態 / 現金模組 / 交易）
- 遠端軟體派送（排程、分群版本更新）
- 行銷內容推播
- EJ（電子日誌）集中收存（機端加密壓縮上傳）
- 程式白名單安全控管（阻擋未授權執行 + 告警）
- 多通道告警（語音／email／SMS／**傳真**）
- 交易分析、故障紀錄、現金流報表

DMS 是成熟產品，但「傳真告警」等跡象顯示其屬較舊世代架構。

## 2. 願景

> 打造一套**雲端就緒、即時、智慧、合規**的次世代 ATM 機隊監控管理平台（AFMP），
> 讓銀行以更低的人力與現金成本，維持更高的機台妥善率與更短的故障修復時間，
> 並提供 MDS 跨銀行營運的產品槓桿。

定位：DMS 的現代化升級／替代，對標 **Diebold Nixdorf Vynamic View**、**NCR Atleos**、**KAL Kalignite KTC**、**ESQ OperationsBridge**、**INETCO**。

## 3. 相對 DMS 的現代化增益（價值主張）

| 面向 | DMS（現況） | AFMP（升級） |
|---|---|---|
| 告警通道 | 語音/email/SMS/**傳真** | App push / IM(LINE/Teams) / Email / SMS / 語音，**傳真退役**；分層升級策略 |
| 即時性 | 輪詢式看板 | WebSocket/SignalR **即時推送**，事件驅動 |
| 現金管理 | 水位監看 | **ML 現金需求預測**（含台灣連假/發薪日）+ 補鈔最佳化 |
| 故障處理 | 告警通知 | **自動分類 + 自動派工 + SLA + 重複故障分析**，整合行動外勤 |
| 對帳 | 交易/現金報表 | **三方對帳**（EJ↔Switch↔Core）+ 差錯案件工作台 |
| 多廠牌 | 以 Hitachi 為主 | 設備抽象層 + 正規化（對齊 XFS4IoT），可納多廠牌 |
| 合規 | 報表 | 金管會**異常提領監控/異常通報**工作流 + 防竄改稽核 + 零信任路線 |
| 架構 | 較舊世代 | .NET 模組化單體 + 多租戶 + on-prem/SaaS 雙拓撲 |

## 4. 業務目標（Outcomes）

1. **提升妥善率**：機台可用率 ≥ 95%（循環/存提機目標 98%+）。
2. **降低現金成本**：閒置現金攜帶成本 ↓ 15–25%、缺鈔事件 ↓ 50%。
3. **縮短修復**：以自動派工 + SLA 計時降低 MTTR。
4. **強化合規**：金管會異常通報 100% 及時、稽核/保留完整、委外監督可舉證。
5. **MDS 營運槓桿**：一套產品服務多家銀行（多租戶），加速導入與標準化。

> KPI 量化指標與量測方式見 `01-stakeholders-and-kpis.md`。

## 5. 範圍邊界（務必貫穿全文件）

- **設計對象**：中央管理平台本體（後端、資料模型、API、儀表板、流程引擎）。
- **不實作**：機端 ATM agent、真實 XFS/廠商協定驅動、實體硬體整合、金管會認證。
- agent 邊界 = **介面合約**（見 `02-integration/20-device-agent-contract-v1.md`）。
- 本環境的端到端展示透過**設備模擬器**（見 `02-integration/22-device-simulator-spec.md`）。

## 6. 非目標（Non-goals, v1）

- 不自建 ATM 交易授權（switch）或核心入帳（core banking）——僅介接其資料做監控/對帳。
- v1 不做完整 ML（先 SARIMA 統計基線，ML 列 v2）。
- v1 不做微服務化（採模組化單體，見 ADR-002）。
